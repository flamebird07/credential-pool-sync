# v7.6.0 Identity Fix: (api_key, base_url, model) → (model, api_key)

**Date**: 2026-07-30
**Root cause**: `switch_next.py` never actually switched to a different credential.

## Problem

The user ran `switch_next.py` but it always claimed "切换成功: Coding-Plan" — the same credential. Investigation showed:

1. **8 Feishu records, but 7 share the same API key** — only "Agent Plan" has a different key
2. **`identity()` used `(api_key, base_url, model)`** but `get_current_model_config()` returned a dict with `default` key (not `model`), so model was always `None`
3. **`normalise_base_url()` added `/v3`** — the config had `api/coding` but the normalized record had `api/coding/v3`, so base_url never matched
4. **Result**: current credential was never found in Feishu records → `ordered_candidates()` always started from the first record → first healthy candidate (Coding-Plan) was always selected

## Root cause chain

```
get_current_model_config() returns {default: "DeepSeek-V4-Flash", ...}
        ↓
identity() reads record.get("model") → None (config has "default" not "model")
        ↓
Current identity = (api_key, base_url, None) — model missing
        ↓
normalise_base_url() adds /v3 — base_url mismatch too
        ↓
Coding-Plan record in Feishu not matched
        ↓
ordered_candidates() starts from first record
        ↓
first_healthy() always selects Coding-Plan first
        ↓
"切换成功" but nothing changed
```

## Fix (4 changes in switch_next.py)

1. **`identity()`**: `(api_key, base_url, model)` → `(model, api_key)` — user's chosen dual-key
2. **`get_current_model_config()`**: map `default` → `model` before returning
3. **`first_healthy()`**: renamed `old_identity` → `current_identity`
4. **`ordered_candidates()`**: explicit `None` handling in identity comparison

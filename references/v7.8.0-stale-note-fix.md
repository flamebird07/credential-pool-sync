# v7.8.0 Stale 备注 Notes Fix

**Date**: 2026-07-30
**Reported by**: User (周公瑾)
**Severity**: High — status shows "✅ 正常" but note says "额度已用完" — contradictory

## Symptom

Feishu credential pool table shows 7 out of 8 records with:
- 状态栏: `✅ 正常` (healthy — health check passed)
- 备注栏: `额度已用完` (quota exhausted — from a previous failed check)

Only the actively-used record (`doubao-seed-evolving`) had a correct note of `验证通过`.

## Root Cause

Health-check success paths in multiple scripts preserved the existing 备注 value
instead of writing "验证通过". Failure paths in some scripts preferred the old
note over the current error, causing stale error messages to survive forever.

### Bug inventory (found by Step 1 Codex review)

1. **sync_credential_pool.py:735-736** — Healthy checks preserve old note via
   `h_note = f.get("备注", "")`. Stale "额度已用完" survives recovery.

2. **sync_credential_pool.py:724-740** — S_R (rate-limited) branch inside the
   `if iv or s == S_R:` block also preserves old note. Should write error or "额度已用完".

3. **sync_credential_pool.py:749-753** — Failed checks (else branch) preserve old note.
   The special `S_U` handling only replaces note when a separate "敞" field exists.

4. **cleanup_feishu_status.py:117** — Successful checks set `new_note = current_note`,
   preserving stale error notes.

5. **cleanup_feishu_status.py:121** — `new_note = current_note or error or "验证失败"`
   prefers old note over current error.

6. **switch_next.py:370** — Old credential unconditionally gets `note="额度已用完"`,
   even when switched for invalid key or network error.

### Additional findings (Step 4 Codex review)

7. **cleanup_feishu_status.py:121** — Failure fallback is always "验证失败", not
   status-specific ("额度已用完" for S_R, "Key 无效" for S_I).

8. **switch_next.py:239-242** — `first_healthy()` writes `note=error` where error
   can be None, so `us()` skips the note update and leaves the old value.

9. **sync_credential_pool.py:668** — Records rejected by `_normalise_record()`
   enqueue `(rid, S_I, None)`, preserving their stale note.

10. **auto_bootstrap.py:try_switch()** — Failed candidates never update Feishu
    status or note at all; only the success path writes back.

## Unified Note Policy

Must be consistent across all scripts:

| Health result | Note value |
|---|---|
| PASS (iv=True) | `"验证通过"` |
| S_R / 限流 | `error or "额度已用完"` |
| S_I / 无效 | `error or "Key 无效"` |
| S_U / 不可用 | `error or "验证失败"` |

**Rule**: Never preserve the existing 备注 value when writing a health-check
result. The note always reflects the *current* check outcome.

## Fix summary

### sync_credential_pool.py
- iv=True → `new_note = "验证通过"`
- S_R → `new_note = e or "额度已用完"`
- else (S_I/S_U) → `new_note = e or ("Key 无效" if s==S_I else "验证失败")`
- `_normalise_record()` reject path: write `"Key 无效"` instead of `None`
- Removed dead code: `_usage_names`, `usage_remove`, `usage_add`

### cleanup_feishu_status.py
- Success: `new_note = "验证通过"` (was `current_note`)
- Failure: `new_note = error or status_specific_fallback` (was `current_note or error or "验证失败"`)

### switch_next.py
- `first_healthy()`: pass `old_status` through target dict
- `main()` old credential: derive note from `old_status` (not hardcoded "额度已用完")
- `first_healthy()` failed candidates: `note=error or status_specific_fallback`

### auto_bootstrap.py
- Pending: failed candidates should update Feishu status/note

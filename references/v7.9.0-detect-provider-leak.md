# v7.9.0 detect_provider() 泄漏修复

## 问题

`detect_provider()` 从 URL 推断出 "ARK" 后，泄漏到了 Hermes 配置的 3 个关键位置：

1. **auth.json pool key**（原 line 721）：`pk = f"{p.lower()}"` → `ark` 而非 `custom:ark`
2. **fallback_providers entry provider**（原 line 482）：`"provider": detect_provider() or "custom"` → `ARK`
3. **config.yaml model provider**（switch_next.py / auto_bootstrap.py）：`"provider": record.get("provider") or detect_provider() or "custom"` → `ARK`

## 影响

- Hermes 不认识 "ARK" 作为 provider 名称，报 `Unknown provider 'ark'`
- 凭据池 key 格式错误，凭据无法被找到
- `custom_providers` 被清空，凭据 key 无法解析

## 修复

### 原则

`detect_provider()` 只用于**飞书显示和回写**，不用于 Hermes 配置。

### 改动

1. **新增 `STANDARD_PROVIDERS`**：`frozenset({'openai', 'anthropic', 'deepseek', 'moonshot', 'dashscope', 'z.ai'})`
2. **新增 `_hermes_pool_key(provider)`**：非标准 provider 自动加 `custom:` 前缀
3. **fallback entry provider**：硬编码为 `HERMES_CUSTOM_PROVIDER = "custom"`
4. **config.yaml model provider**：switch_next.py 和 auto_bootstrap.py 中硬编码为 `"custom"`
5. **`custom_providers` 保护**：新增 `_strip_version_suffix()` 模糊匹配，避免因 `/v3` 后缀差异误删
6. **已耗尽凭据过滤**：S_R 且错误包含 "额度已用完"/"quota exhausted" 的记录跳过

## 验证

```bash
# auth.json pool key 格式
$ python -c "import json; a=json.load(open('auth.json')); print(list(a['credential_pool'].keys()))"
['custom:ark']

# config.yaml provider
$ python -c "import yaml; c=yaml.safe_load(open('config.yaml')); print(c['model']['provider'])"
custom
```

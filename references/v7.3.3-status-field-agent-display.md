# v7.3.3 状态栏 Agent 标记显示修复

Date: 2026-07-30
User request: 飞书表格状态栏应显示当前哪个 Hermes 正在使用具体 API Key，只显示在用的一个，不是所有加载进凭证池的 API Key。

## 根因

所有三个脚本（sync_credential_pool.py, cleanup_feishu_status.py, switch_next.py）都将 Agent 使用信息写入 **备注** 字段，而 **状态** 字段仅显示健康状态（"✅ 正常"）。用户无法从状态栏看到哪个 Hermes 正在使用哪个凭证。

## 修复思路

将 Agent 使用信息从备注栏迁移到状态栏。状态栏按以下规则显示：

| 条件 | 状态栏显示 |
|---|---|
| 有效 + 当前 Agent 在用 | `status_add()` → "🔄 周公瑾使用中" |
| 有效 + 非当前 Agent | `status_remove()` → "✅ 正常" |
| 无效/限流 | `health_status()` → "❌ 无效"/"⛔ 限流" |

备注栏不再包含 Agent 标记，只保留普通说明文字。

## 修改文件

### sync_credential_pool.py

1. `_sync_unlocked()` 状态栏回写逻辑（行 659-668）：
   - 有效且匹配 `current_identity` → `status_add(f.get("状态", ""), agent_name)`
   - 有效但不匹配 → `status_remove(f.get("状态", ""), agent_name)`
   - 无效 → `health_status(iv, s, e)`
   - 备注保留原始值：`h_note = f.get("备注", "")`

2. 无效凭证的备注（行 678-685）：
   - 不再调用 `usage_remove()`，备注保留原始值

3. 删除 `clear_current(tok)` 调用（行 710）：
   - 注释掉该调用，因为每个记录自己维护状态

4. 删除 `clear_current()` 函数定义（行 180-188）：
   - 死代码，不再被调用

### cleanup_feishu_status.py

1. 导入 `status_add`/`status_remove` 替代 `usage_add`/`usage_remove`

2. `health_status` 变量重命名为 `probe_status`（行 106）：
   - 避免与导入的 `health_status()` 函数名冲突
   - 原代码中 `health_status` 变量引用了 `S_U`，但 `S_U` 未导入时 `NameError`

3. 状态栏逻辑（行 110-120）：
   - 匹配当前 → `status_add(current_status, agent_name)`
   - 不匹配 → `status_remove(current_status, agent_name)`
   - 无效 → `health_status(False, probe_status, error)`
   - 备注保留原始值

### switch_next.py

1. 导入 `status_add`/`status_remove`

2. 删除 `_usage_names`/`usage_add`/`usage_remove` 函数（行 75-88）

3. 切换后飞书回写（行 395-406）：
   - 旧凭证：`status_remove(old_status, agent_name)`，备注写"额度已用完"
   - 新凭证：`status_add(current_status, agent_name)`，备注写"验证通过"

## 验证

完整同步后，飞书表格状态栏的预期显示：
- 当前正在用的凭证：🔄 周公瑾使用中
- 其他有效凭证：✅ 正常
- 多个 Hermes 共用时：🔄 周公瑾+甘宁使用中
- 备注栏不再显示 Agent 使用信息

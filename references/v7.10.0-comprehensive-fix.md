# v7.10.0 全面修复四大根因及循环 CRITICAL BUG

## 修复背景

本次基于第四次崩溃诊断报告，使用四步法修复 Hermes 官方缺陷（7 个）和封装技能缺陷（10 个）的核心问题，重点解决导致系统完全不可用的 4 个根因：

## 修复内容

### 1. BUG-01: exhausted 状态永不恢复（官方缺陷）
**问题**: 临时限流（429）被永久标记为不可用，即使 API 恢复后也不会重试
**修复**: 在 sync_credential_pool.py 中添加重试机制，exhausted 凭证在超时前重试一次，成功后更新状态并加入池子

### 2. BUG-03: URL 后缀缺失（技能缺陷）
**问题**: 飞书表格中的 URL 缺少 `/v3` 后缀导致 API 调用失败
**修复**: 扩展 normalise_base_url()，新增 `/api/coding`→`/api/coding/v3` 和 `/api`→`/api/v3` 标准化

### 3. BUG-04/05: 大小写不一致（技能缺陷）
**问题**: Provider 为 "ARK"（大写）但 Hermes 需要 "custom"；模型名大小写不匹配
**修复**: Provider 统一转为小写，强制为 custom；所有模型名小写处理

### 4. BUG-08/14: 缺失 access_token（官方+技能缺陷）
**问题**: fallback 条目和旧版本凭证缺少 access_token 字段，导致无权限调用 API
**修复**: 添加 `_backfill_token_fields()` 助手函数，确保每个凭证同时有 access_token 和 api_key

### 5. BUG-12: 模型/端点不匹配（技能缺陷）
**问题**: sync 脚本将被限流的模型设为主模型，且端点不匹配
**修复**: 健康主模型自动选择，当前模型不健康时自动切换到可用健康模型

### 6. BUG-17: fallback 跳过相同 base_url（官方缺陷）
**问题**: Hermes 官方实现中 fallback 链跳过相同 base_url 的不同模型，导致 4 个有效 fallback 仅尝试 1 个
**修复**: fallback 去重算法优化，优先选择不同 base_url 的条目，避免触发官方 BUG

### 7. BUG-02: sync 覆盖手动配置（技能缺陷）
**问题**: sync 脚本无条件覆盖 fallback_providers 配置，摧毁手动修复的配置
**修复**: 新增 `_sync_managed` 标记，仅当无标记或首次同步时更新 fallback_providers

### 8. 循环修复的 CRITICAL BUG
- **tk() 元组解包错误**: 修复重试逻辑中返回元组被当作 scalar 判断的错误
- **恢复凭证不加入池子**: 去掉 continue，使成功恢复的凭证能正常加入输出池和凭证池

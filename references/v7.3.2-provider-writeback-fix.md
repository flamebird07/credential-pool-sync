# v7.3.2 Provider Write-Back Fix

2026-07-30 — 四步法修正：修复 Provider 字段回写和状态更新问题。

## 问题

飞书表格 UI 没有实时显示凭证池状态：
1. Provider 字段显示 "custom" 而不是正确的 Provider 名称
2. 每条凭证的状态没有更新
3. 4 个脚本对 "custom" 的处理不一致

## 根因

`_normalise_record()` 在本地正确推断 Provider（"custom" → "ARK" 等），但：
- `sync_credential_pool.py` 的 `url_updates` 条件只检查 `not original_provider`，遗漏 "custom"
- `switch_next.py` 的 `_normalise_record()` 只检查 `not provider`，遗漏 "custom"
- `switch_next.py`/`auto_bootstrap.py` 的 config.yaml 写入使用 `detect_provider() or "custom"` 覆写掉记录中的正确 Provider
- `cleanup_feishu_status.py` 的清理流程完全不更新 Provider 字段
- `cleanup_feishu_status.py` 缺少 `S_U` 导入，引用时会 NameError

## 修复清单

| 文件 | 修复 |
|------|------|
| `sync_credential_pool.py:648` | `url_updates` 条件改为 `detected_provider and (not original_provider or original_provider.lower() == "custom")` |
| `switch_next.py:184` | `_normalise_record()` 条件改为 `not provider or provider.lower() == "custom"` |
| `switch_next.py:266` | `update_runtime_main_model()` 使用 `record.get("provider") or detect_provider() or "custom"` |
| `auto_bootstrap.py:66` | `write_runtime_config()` 使用 `record.get("provider") or detect_provider() or "custom"` |
| `cleanup_feishu_status.py:8` | 增加 `S_U` 导入 |
| `cleanup_feishu_status.py:86-138` | 清理循环中推断 Provider 并回写 |

## 核心原则：跨脚本 Provider 一致性

所有脚本必须遵循相同的 Provider 标准化逻辑：

```python
# 优先级：记录字段中的 Provider → detect_provider() 推断 → "custom" 兜底
provider = record.get("provider") or detect_provider(base_url) or "custom"
```
